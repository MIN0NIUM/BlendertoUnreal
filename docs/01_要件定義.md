# 01. 要件定義

- ドキュメントバージョン: v0.1（たたき台）
- 最終更新: 2026-10-09
- ステータス: **要レビュー**

---

## 1. 背景と課題

DCCツールで作ったメッシュを Unreal Engine に持ち込む作業は、手順自体は定型的でありながら設定項目が多く、以下の事故が恒常的に発生する。

| よくある事故 | 原因 |
|---|---|
| スケールが 1/100 または 100倍 | Blender(m) と UE(cm) の単位差、FBX Export の Scale 設定 |
| 向きが 90度 違う | Blender(Z-up/-Y-forward) と UE(Z-up/X-forward) の軸差 |
| ピボットが原点にない | オブジェクト原点を揃え忘れ |
| スケルトンが毎回新規生成され、既存アセットと互換がなくなる | インポート時に Skeleton を選び忘れ |
| コリジョンが入らない / 名前が違う | `UCX_` 等の規約違反 |
| LOD が別アセットになる | LOD グループ化の方法を誤る |
| マテリアルスロットの順番が変わり、既存の割当が壊れる | スロット順の非決定性 |
| 法線 / スムージングが崩れる | FBX の Smoothing 設定、カスタム法線の未出力 |
| 再インポートで手作業の設定が飛ぶ | 設定が人間の記憶に依存 |

→ **設定を「人間の記憶」ではなく「データ」として持ち、再現可能にする**ことが本ツールの本質。

## 2. 目的

1. アーティストが **操作1回**（＝ワンポチ）でメッシュを UE アセット化できる
2. インポート設定を **宣言的なデータ（マニフェスト）** として持ち、誰が何回やっても同じ結果になる
3. 事故になる条件を **書き出し前に検出して止める**（UEに持ち込んでから気づかない）
4. 設定の決定ロジックをコード化し、プロジェクト規約として共有・バージョン管理できる

## 3. ユーザー

| ペルソナ | 使い方 | 求めるもの |
|---|---|---|
| モデラー（主） | Blenderで作業 → ワンポチ → UEで確認 | 考えずに正しく入ること。失敗理由が日本語で分かること |
| テクニカルアーティスト | 規約・プリセットの整備、不具合対応 | 設定が外部ファイルで管理でき、拡張できること |
| （将来）CI/バッチ | 自動ビルド時の一括インポート | GUIなしで同じ処理が走ること |

## 5. 成功基準

| 指標 | 目標 |
|---|---|
| 操作回数 | DCC上のクリック **1回**（設定済みの状態から） |
| 単体メッシュの所要時間 | 10秒以内（書き出し〜アセット生成完了） |
| スケール・軸の事故 | **0件**（バリデーションで機械的に担保） |
| 再インポート後の設定保持 | UE側で変更した Nanite/LOD/コリジョン設定が維持される |
| 失敗時の挙動 | 必ず原因を日本語で提示。部分的に壊れたアセットを残さない |
| 冪等性 | 同じ入力 → 同じ出力（差分がないなら再保存もしない） |

## 7. 非機能要件

- **決定性**: 同一入力に対し常に同一出力。実行順やGUI状態に依存しない
- **冪等性**: 何度実行しても壊れない。失敗時はロールバック（中途半端なアセットを残さない）
- **可観測性**: DCC側とUE側のログを共通の `run_id` で突合できる
- **移植性**: UE側のコア処理（マニフェスト → アセット）は、起動方法（手動ボタン/HTTP/CI）に依存しない純粋な処理として実装する
- **拡張性**: プロジェクト固有の規約はコード改変ではなく **プリセットファイル** で差し替える
- **安全性**: UE の Content 以下に対する破壊的操作（上書き・削除）は、対象パスのホワイトリストと明示確認を介する
