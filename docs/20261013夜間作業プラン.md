### 1.1 RC 拒否の原因切り分け — **原因確定**（2026-10-13 夜 / 実測 + ソース確認）

ユーザーが UE を再起動（PID 83888）しても拒否されたため、**段階的にプローブ**しました。
詳細は [docs/99 P-29](99_作業ルール.md) に記録済み。

| 段 | 試したこと | 結果 |
|---|---|---|
| ① | `GET /remote/info` | **200** |
| ② | プロパティ読み（`EditorStyleSettings.SelectionColor`） | **200** |
| ③ | 非 Python 関数（`KismetSystemLibrary.GetEngineVersion`） | 400 `Executing **function** ... is not allowed` |
| ④ | `PythonScriptLibrary.ExecutePythonCommandEx` | 400 **`**Object** Default__PythonScriptLibrary cannot be accessed remotely`** |

**②が 200 だったことで、計画時の疑い2つが消えました**:

- **`AllowlistedClients` はシロ**（`127.0.0.1` は範囲外なのに読み書きが通る）→ **触らない**
- **`bEnforcePassphraseForRemoteClients` もシロ**（ヘッダ無しで 200）

**③と④でエラーの文面が違う**のが決定的でした。③は「関数が許可リストに無い」、
④は「**オブジェクト**に遠隔アクセスできない」＝ **より手前の Python 専用ゲート**。
→ 原因は `CustomAllowedRemoteFunctionCalls` ではなく
**`bEnableRemotePythonExecution` が実行時に効いていないこと**。

**そして原因が確定しました（2026-10-13 深夜 / エンジンのソースで裏取り）。**
`Config/DefaultEngine.ini` に追記した設定は、**1つも読まれていませんでした**。

```cpp
// UE_5.8/.../RemoteControlCommon/Public/RemoteControlSettings.h:180
UCLASS(config = RemoteControl)
class REMOTECONTROLCOMMON_API URemoteControlSettings : public UDeveloperSettings
```

`config = RemoteControl` なので、この設定は **`RemoteControl.ini` 階層からしか読まれない**。
正しい置き場所は **`Config/DefaultRemoteControl.ini`**。`DefaultEngine.ini` では**無視される**。

| ソースで確かめたこと | 場所 | 結論 |
|---|---|---|
| ④の拒否条件 | `RemoteControlModule.cpp:2563` | **`bEnableRemotePythonExecution` が false のときだけ**弾く。他の設定は見ていない |
| `ExecutePythonCommandEx` は既定で許可か | `RemoteControlSettings.cpp:25` | **されていない** → `+CustomAllowedRemoteFunctionCalls` は**必須** |
| `bRestrictServerAccess=True` で loopback が弾かれるか | `RemoteControlDefaultPreprocessors.cpp:419` | **弾かれない**（`127.0.0.1` は判定対象外）。②が 200 だった理由 |
| `bSecuritySettingsReviewed` の役割 | 全ソース検索 | **宣言以外に参照が無い** → 実行時のゲートには無関係。**前の疑いは外れ** |

> **教訓（docs/99 P-29 に記録）**: `.ini` に書いたのに効かないときは、
> キーより先に**ファイル名**を疑う。`UCLASS(config = Foo)` なら `DefaultFoo.ini`。
> 手がかりは最初から出ていた — UE がユーザー設定を書く先が
> `Saved/Config/WindowsEditor/**RemoteControl**.ini` という名前だった。

### M-1. R-5: Remote Control 設定をプロジェクト側に固定 ★ブロッカー解消

**なぜ**: エディタを再起動すると Python 実行の許可が消える（P-29）。
今回の実測で **`CustomAllowedRemoteFunctionCalls` の行そのものが消えていた**ことが分かり、
**`Saved/Config` に置く限り再発する**と判断できた。チーム配布でも同じ事故が起きる。

**作業**

1. **`UEProject/OnePochiPlayground/Config/DefaultRemoteControl.ini` を新規作成**する
   （`DefaultEngine.ini` では**読まれない** → §1.1。最初は Engine.ini に追記してしまい、
   **再起動しても拒否されたことで判明した**。Engine.ini 側の追記は撤去済み）

   ```ini
   [/Script/RemoteControlCommon.RemoteControlSettings]
   bEnableRemotePythonExecution=True
   bRestrictServerAccess=True
   bAllowAnyRemoteFunctionCall=False
   bAllowConsoleCommandRemoteExecution=False
   bSecuritySettingsReviewed=True
   +CustomAllowedRemoteFunctionCalls=(ClassPath="/Script/PythonScriptPlugin.PythonScriptLibrary",FunctionName=("ExecutePythonCommandEx"),bAllowChildClasses=False)
   ```

   - **`bAllowAnyRemoteFunctionCall=False` を維持**（何でも呼べる状態にはしない）。
     許可する関数は **`ExecutePythonCommandEx` の1件だけ**、コンソールコマンドの遠隔実行も False
   - **`bRestrictServerAccess=True` のまま**＝緩めない。`127.0.0.1` は許可リストの判定対象外なので
     自分のアクセスは通る（`RemoteControlDefaultPreprocessors.cpp:419` で確認）
   - **`AllowlistedClients` は触らない。**§1.1 の②で**シロと実測できた**ため、
     根拠の無い変更をしない（計画時は「127.0.0.1 に絞る」としていたが取り下げ）
   - **`bSecuritySettingsReviewed=True` を含めた**。これは「セキュリティ設定を確認した」という
     意味のフラグなので、**ユーザーに代わって立てたことを明示**して報告する。
     なお実行時のゲートからは参照されていない（§1.1）
   - `FunctionName=(...)` の綴りは **UE 自身が `Saved` に書いた形**をそのまま使った
2. 診断スクリプト `tools/check_rc_config.py` を作る（**UE を起動しなくても動く / 日本語出力**）
   - `Config/DefaultRemoteControl.ini` と `Saved/Config/WindowsEditor/RemoteControl.ini` を読み、
     必要な項目が**どちらに / どんな値で**入っているかを表で出す。
     **`DefaultEngine.ini` に同セクションがあれば「読まれない」と警告する**（同じ罠を二度踏まない）。
     Saved 側に違う値が残っていたら「打ち消されています」と警告する（Saved が後勝ち）
   - RC サーバへ**段階的にプローブ**して、拒否されたときに**どの設定が原因かを切り分ける**
     （① サーバ到達 → ② 許可リスト外のオブジェクト呼び出し → ③ `PythonScriptLibrary` 呼び出し）
   - 失敗時は **何をどこに入れればよいかを日本語で提示**する
3. `tools/run_tests.py` / `tools/run_roundtrip_test.py` が `--via-rc` で 400 を受けたとき、
   **このスクリプトの実行を促すメッセージ**を出す
4. **UE 再起動後の確認はユーザー作業**（A-19）。再起動せずに効かせる方法は無い
   （`.ini` は起動時に読まれる）

### M-2. R-4: テクスチャの発見規則を実装（DCC 側）★本命

**なぜ**: UE 側のテクスチャ取り込みは実装済み・API 名も実機確定済みなのに、
**`materialSlots[].textures` を Blender 側が一度も出力していない**ため渡す対象が 0 件。
ここが埋まると **P5 の最後の DoD が検証可能**になる。

**方針**: ユーザー回答どおり **案1（フォルダ走査）**。**ただし §2.2 D-1 のとおり綴りを 2 系統許す。**

**発見規則（実装する仕様）**

走査対象は `source.textureFolder`（既定 `textures/`）**直下のみ**（**再帰しない** ← `megascan/` のような
元素材フォルダを巻き込まないため）。ファイル名の語幹を次の順で照合する:

| 優先 | パターン | 例（スロット `M_Crate_Body` / アセット `Crate_01`） |
|---|---|---|
| 1 | `T_<スロット名から `M_` を外した名前>_<サフィックス>` | `T_Crate_Body_BC` ← **案1 の本来の形 / S-11 の実物** |
| 2 | `T_<スロット名そのまま>_<サフィックス>` | `T_M_Crate_Body_BC`（保険。アーティストはこう付けがち） |
| 3 | `T_<アセット名>_<サフィックス>`（**単一スロットのときだけ**） | `T_Crate_01_BC` |

- **サフィックスは [docs/04 §3](04_命名規約.md) の表に載っているものだけ**
  （`_BC` `_D` `_N` `_ORM` `_M` `_R` `_AO` `_E` `_MSK`）。大文字小文字は区別しない
- 拡張子は `.png` `.tga` `.jpg` `.jpeg` `.tif` `.tiff` `.exr`。**同じサフィックスで複数見つかったら
  この順で 1 つを採用し、採用しなかったものを警告に出す**（黙って選ばない）
- 見つからなかったサフィックスは**何も出力しない**（空文字やダミーを入れない）
- **`importTextures` が false でも `textures` は出力する**。
  「発見（DCC 側の事実）」と「取り込むか（UE 側の方針）」を分ける（設計方針 D-3 / D-5）

**実装**

1. `onepochi/core/texture_discovery.py` を新規追加 — **bpy 非依存の純粋ロジック**
   - `candidate_stems(slot_name, asset_name, single_slot)` → 照合する語幹の候補（優先順）
   - `discover(slot_names, asset_name, file_names)` →
     `{slot_name: {"_BC": "T_...jpg", ...}}` と警告のリスト
   - **ファイルシステムに触らない**（ファイル名のリストを受け取る）ので単体テストが書ける
2. `bl/pipeline.py` の `_material_slots_manifest()` に配線し、`textures` を入れる
   - 走査する実フォルダは `source.assetFolder` + `source.textureFolder`
   - **フォルダが無い / 空でもエラーにしない**（情報として記録する）
3. `bl/validate.py` に警告ルールを追加（**エラーにはしない** / 書き出しは止めない ← Q-06）

   | ID | 内容 | 重大度 |
   |---|---|---|
   | V-110 | スロット `M_xxx` に対応するテクスチャが 1 枚も見つからない | 警告 |
   | V-111 | 同じサフィックスのテクスチャが複数見つかった（どれを採用したかを明記） | 警告 |
   | V-112 | `T_` で始まらない / 使えない文字を含むテクスチャがフォルダにある | 警告 |
   | V-113 | `_N`（法線）が**非可逆圧縮形式（`.jpg` / `.jpeg`）** | 警告 |
   | V-114 | `_N` の画像の色空間が Blender 上で `Non-Color` でない（§2.2 D-4） | 情報 |

4. 単体テスト `tools/dcc_blender/tests/test_texture_discovery.py`
   - 3 系統の綴り / 大文字小文字 / 拡張子の優先順 / 重複 / 未知サフィックス /
     再帰しないこと / マルチスロット（S-03 の `M_Slot_A/B/C`）で**取り違えないこと**
