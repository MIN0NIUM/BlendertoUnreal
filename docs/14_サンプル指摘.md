## 1. S-04 `04_skeletal_minimal.blend`

### 1.1 ご質問への回答: root ボーンの位置は**正しい**

| 確認項目 | 実測値 | 判定 |
|---|---|---|
| `root` ボーンの head（ローカル） | `(0, 0, 0)` | ✅ |
| `root` ボーンの head（ワールド） | `(0, 0, 0)` | ✅ |
| Armature オブジェクトの位置 / 回転 / スケール | `(0,0,0)` / `(0,0,0)` / `(1,1,1)` | ✅ |
| メッシュのワールド BBox（Z） | `0.0` 〜 `1.0` m | ✅ 床に接地 |
| ルートボーンの本数 | 1本（`root`） | ✅ |
| ポーズのトランスフォーム | 全ボーン単位行列 | ✅ |
| シーン単位 | METRIC / scale 1.0 / meters | ✅ |

**原点・床接地・単root という UE の前提は満たしている。** 位置の修正は不要。

### 1.2 ただし root ボーンの「長さ」がほぼゼロ

| 項目 | 実測値 |
|---|---|
| `root.head_local` | `(0, 0, 0)` |
| `root.tail_local` | `(0, 0, 0.000002)` |
| `root.length` | **`0.000002` m（2 µm）** |

Blender 上では tail を head に重ねても最小長にクランプされるため、**実質ゼロ長ボーン**になっている。

- ゼロ長ボーンは FBX 書き出し時に**向き（roll）の算出が不定**になる
- UE 側で退化ボーンとして警告が出る可能性がある（**要検証**）
- Blender のビューポートでも UE のスケルトンツリーでも**見えない**ため、事故に気づけない

**修正依頼 A-1**: `root` の tail を伸ばして実体のある長さにしてください。推奨 **0.1 m**。

> Edit Mode で `root` を選び、Item パネルで Tail Z を `0.1` に。
> 向き（+Z か +Y か）は UE 側の実測が済んでいないため、**まずは現状と同じ +Z のまま**で構いません。
> ボーン軸の変換規則は P3 でこのサンプルを使って実測し、`docs/02_仕様書.md` §6 に確定値を書きます。

### 1.3 ボーン名・マテリアル名の先頭にスペースが入っている

| 種別 | 実測の名前 | 問題 |
|---|---|---|
| ボーン | `" bone_01"` | **先頭にスペース** |
| ボーン | `" bone_02"` | **先頭にスペース** |
| 頂点グループ | `" bone_01"` | 同上（ボーン名に追従） |
| マテリアル | `" M_Dummy_Body"` | **先頭にスペース** |

バリデータ（V-003 / V-003c）でエラーになり**書き出しはブロックされる**。
UE 側でも先頭スペース付きのボーン名は、UI でほぼ判別できないまま
リターゲットや名前引きの Blueprint を壊すため、**データ側で直すのが正しい**。

**修正依頼 A-2**: 先頭スペースを削除して `bone_01` / `bone_02` / `M_Dummy_Body` にしてください。

> **ボーンをリネームすれば、対応する頂点グループは Blender が自動で追従します。**
> 先に頂点グループだけ直すと対応が切れるので、**ボーン名を先に直してください。**

### 1.4 `bone_02` にウェイトが乗っていない

| 項目 | 実測値 |
|---|---|
| 頂点数 | 84 |
| 未割当の頂点 | **0**（✅ 仕様どおり） |

**修正依頼 A-3**: `bone_02` にもウェイトを配分してください（自動ウェイトの再実行で十分です）。

> bone_02 が動かないと検証にならない**ため直しておきたいです。

### 1.5 ウェイトの正規化が一部崩れている

| 項目 | 実測値 |
|---|---|
| ウェイト合計が 1.0 でない頂点 | **24 / 84** |
| 最も 1.0 から離れた合計値 | `0.997486` |

ズレは最大 0.0025 で、UE はインポート時に正規化するため**実害は小さい**。

**こちら側の対応（修正依頼ではありません）**: V-069 を
**ズレ < 0.01 は警告 / それ以上はエラー**の二段にします。この程度で止めるのは過剰なので。

気になる場合は Weight Paint モードで `Weights > Normalize All` を実行してください。

### 1.6 その他（任意）

| 項目 | 実測値 | 仕様 (`samples/README.md`) |
|---|---|---|
| Armature オブジェクト名 | `Armature` | `Dummy_Armature` |
| Armature データ名 | `root` | （指定なし） |

命名規約上は `Armature` でも通る（`^[A-Za-z][A-Za-z0-9_]*$`）ので**ブロックしません**。
ただし S-05 と並べたときに見分けがつかないため、リネーム推奨。

### 1.7 設計メモ（ユーザー作業は不要）

`root` が `use_deform = True` かつウェイトを持っている。
UE の慣習では root は変形に関与しない純粋なトランスフォームボーンだが、
**FBX 書き出しで `use_armature_deform_only = True` を使うと、ウェイトの無いボーンが削除される。**

> **この項の当初の結論（`use_armature_deform_only` を使わない）は変更しました。**
> キャラクターリグでは IK / コントロールボーンを落としたいので、この設定は**使う価値がある**。
> 代わりに「root が消える」事故を**バリデーションで防ぐ**ことにした。

最終的な方針:

| 項目 | 決定 |
|---|---|
| `use_armature_deform_only` | **`true` のまま使う**（`project_default.json`） |
| root が消える事故 | **V-062 でエラー**にする（deform_only が有効かつ root が非 deform のとき） |
| マニフェストのボーン一覧 | `exported_bone_names()` で**実際に書き出される集合を予測**して載せる |

**実測で予測の正しさを確認済み**（2026-10-10 / S-04 をメモリ上で改変して検証）:

| 条件 | 予測 | FBX 内の実際 | 一致 |
|---|---|---|---|
| `bone_02` を `use_deform=False` + 頂点グループ削除 / `deform_only=true` | `['bone_01', 'root']` | `['bone_01', 'root']` | ✅ |

マニフェストのボーン一覧も `['root', 'bone_01']` となり、**FBX の中身と一致**した。
つまり `deform_only` を有効にしても、UE 側の突き合わせに使う予測値は信頼できる。

## 3. S-06 `06_skeletal_morph.blend` — 作り直しが必要

目的は **Shape Keys → Morph Target の取り込み検証**。前提として
**Skeletal Mesh でなければならない**（Morph Target は Skeletal Mesh の機能）。

| 項目 | 実測値 | 問題 |
|---|---|---|
| オブジェクト | `Sphere`（MESH 1個のみ） | — |
| **Armature** | **存在しない** | ✖ これは Static Mesh |
| **Armature モジファイア** | **無し** | ✖ |
| **頂点グループ** | **無し** | ✖ スキンされていない |
| Shape Key | `Close`, `Open`, `Smile` | ✖ **先頭（Basis）が `Close`** |
| マテリアルスロット | **0個** | ✖ 未割当（ファイル内に未使用の `MI_Quinn_01` / `MI_Quinn_02` あり） |
| オブジェクト位置 | `(0, 0, 1.24985)` | ✖ 未適用のトランスフォーム |
| ワールド BBox（Z） | `0.24985` 〜 `2.24985` | ✖ 床から 25 cm 浮いている |

### Shape Key の先頭ブロックについて

Blender では **Shape Key リストの先頭が基準形状（通常 `Basis`）**で、
UE に渡るのは **2番目以降だけ**です。現状は先頭が `Close` なので:

- `Close` が「変形なしの基準」として扱われる
- UE 側に出る Morph Target は `Open` と `Smile` の2つだけ
- `Close` という名前の Morph Target は**作られない**

**修正依頼 C-1**: S-04 の修正版をコピーして作り直してください。
1. `04_skeletal_minimal.blend`（修正後）を `06_skeletal_morph.blend` として保存し直す
2. `Dummy_Body` に Shape Key を追加 — **先頭は `Basis`（空のまま）**、続けて `Smile` / `Blink_L`
3. `Smile` / `Blink_L` はそれぞれ**目に見えて違う形**に変形させる（頂点を数個動かせば十分）
4. マテリアルは `M_Dummy_Body` 1スロット
5. オブジェクトの位置は `(0,0,0)`、メッシュは床に接地

> `MI_Quinn_01` / `MI_Quinn_02` は UE5 マネキン由来の未使用マテリアルのようです。
> `MI_` は**マテリアルインスタンス用のプレフィックス**なので、
> Blender 側のマテリアル名としては規約違反になります（使うなら `M_` 始まり）。
> 未使用なら削除で構いません。
