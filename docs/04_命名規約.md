# 04. 命名規約

- 最終更新: 2026-10-13（§3 にテクスチャの**発見規則**を追記 / R-4）
- ステータス: **承認済み（Q-10）**。以降の変更は要相談

本規約は、広く使われている UE5 のスタイルガイド（Epic Games 系の慣習 / `Allar/ue5-style-guide`）を土台にしています。

## 0. 全体に効く鉄則

| # | 規則 | 対象 |
|---|---|---|
| N-1 | **先頭は英字。数字・記号で始めてはならない** | アセットフォルダ名 / .blend ファイル名 / オブジェクト名 / コレクション名 / マテリアル名 / ボーン名 / UE アセット名 **すべて** |
| N-2 | 使用可能文字は `A-Za-z0-9_` のみ | 同上 |
| N-3 | 2バイト文字（日本語）・空白・ハイフン・ドットは禁止 | 同上 |
| N-4 | 大文字小文字のみの差異で区別してはならない（Windows で衝突する） | 同上 |

> N-1 はユーザー指示（2026-10-10）。`samples/` 配下のサンプルデータだけは並び順のため
> `01_static_minimal` のように先頭数字を許容する（バリデータで例外指定可）。

## 1. Unreal Engine 側アセット

| アセット種別 | プレフィックス | 例 |
|---|---|---|
| Static Mesh | `SM_` | `SM_Crate_01` |
| Skeletal Mesh | `SK_` | `SK_Dummy_01` |
| Skeleton | `SKEL_` | `SKEL_Dummy` |
| Physics Asset | `PHYS_` | `PHYS_Dummy` |
| Material | `M_` | `M_Crate_Body` |
| Material Instance | `MI_` | `MI_Crate_Body_Red` |
| Texture | `T_` | `T_Crate_01_BC` |
| Animation Sequence | `A_` | `A_Dummy_Idle`（スコープ外・参考） |

### 1.1 命名の構造

```
<プレフィックス>_<ベース名>_<バリアント>
          SM_       Crate      _01
```

- 使用可能文字: `A-Z a-z 0-9 _`
- 先頭は英字
- 日本語・空白・ハイフン・ドットは不可
- バリアントは 2桁ゼロ埋め（`_01`, `_02`）

## 2. DCC 側（Blender）オブジェクト

### 2.1 基本

| 用途 | 命名 | 例 |
|---|---|---|
| Static Mesh 本体 | `<BaseName>` または `SM_<BaseName>` | `Crate_01` |
| Skeletal Mesh 本体 | `<BaseName>_Body` 等 | `Dummy_Body` |
| Armature | `<BaseName>_Armature` | `Dummy_Armature` |

> DCC側のオブジェクト名からUEアセット名を導出する規則は、マニフェストで明示する方式（方針 D-2）のため厳格ではありません。
> ただし **UI でアセット名を自動補完する** ため、上記に従っていると手数が減ります。

### 2.2 LOD —— コレクション方式（決定: Q-11 / **2026-10-11 実測で改訂**）

**LOD の段は「コレクション名」で表す。**判定にオブジェクト名は使わない。

```
Crate_01/                 ← アセット用コレクション（名前 = アセット名）
├── LOD0/                 ← 必須。欠番不可
│   └── Crate_01          ← 素のアセット名
├── LOD1/
│   └── Crate_01_LOD1     ← LOD1 以降は _LOD<n> を付ける（下記の理由）
├── LOD2/
│   └── Crate_01_LOD2
├── Collision/
│   ├── UCX_Crate_01_01
│   └── UBX_Crate_01_01
└── Sockets/
    └── SOCKET_Lid
```

| 規則 | 内容 |
|---|---|
| コレクション名 | `LOD0` / `LOD1` / ... 連番・欠番なし。`LOD0` 必須 |
| LOD 階層なし | LOD コレクションが存在しない場合は「LOD0 のみ」とみなす（単純なアセットに階層を強制しない） |
| **オブジェクト名** | **LOD0 は素のアセット名（`Crate_01`）、LOD1 以降は `<アセット名>_LOD<n>`。**Blender はオブジェクト名をファイル全体で一意に保つため、**同名にはできない**（下記） |
| 予約コレクション名 | `LOD<n>` / `Collision` / `Sockets` は予約語。他の用途に使わない |

> **改訂の理由（実測 / [docs/99](99_作業ルール.md) P-21）**: 旧版は
> 「LOD 間でオブジェクト名が同じでよい（コレクションで区別されるため）」としていましたが、
> **Blender ではこれが実現できません。**`bpy.data.objects` の名前はファイル全体で一意で、
> 2 個目に同じ名前を代入しても**例外は出ず黙って `Crate_01.001` になります**
> （Blender 5.2.2 LTS で実測）。しかも `.001` はドットを含むため
> **V-003 で弾かれます**。コレクションは名前空間を作りません。
>
> **LOD の段の判定はコレクション名だけで行う**実装（`naming.parse_lod_collection()`）なので、
> オブジェクト名のサフィックスは判定に影響しません。
> 書き出し時にマニフェストの `levels[].sourceNode` に記録されるだけです。

> UE の Static Mesh の LOD は**アセット内部**に格納されるため、LOD が UE のアセット一覧を増やすことはない。
> UE 側は `levels[].sourceFile`（LOD ごとの FBX）を
> `StaticMeshEditorSubsystem.import_lod()` で LOD スロットに読み込む
> （**GUI / Remote Control 専用。commandlet では使えない** / [docs/99](99_作業ルール.md) P-5）。

### 2.3 コリジョン

| プレフィックス | 形状 | 例 |
|---|---|---|
| `UCX_` | 凸包 | `UCX_Crate_01_01` |
| `UBX_` | ボックス | `UBX_Crate_01_01` |
| `USP_` | スフィア | `USP_Crate_01_01` |
| `UCP_` | カプセル | `UCP_Crate_01_01` |

形式: `<Prefix>_<対象メッシュ名>_<2桁連番>`

**連番は省略できます**（UE の規約でも省略可）。ただし**省略は推奨しません**
（`V-040` の警告が出ます）。理由は次のとおりです。

> **`UCX_Crate_01` は2通りに読めます。**
> (a) 本体 `Crate_01` の連番なし / (b) 本体 `Crate` の 1 番。
> しかも `<名前>_<2桁>` は本規約の標準的なメッシュ名（`Crate_01`）なので、
> **文字列だけでは決められません**。
>
> ツールは**書き出し対象の本体メッシュ名と照合して、実在する読み方を優先**します
> （`naming.parse_collision_name(name, known_bodies)`）。それでも
> **`UCX_Crate_01_01` と書いておけば曖昧さがそもそも生じません**。
> 実測で踏んだ事例: S-08（→ [docs/99 P-19](99_作業ルール.md)）。

### 2.4 ソケット

| 命名 | 例 |
|---|---|
| `SOCKET_<SocketName>` | `SOCKET_weapon_r` |

- Blender の Empty オブジェクトで表現
- Static Mesh: 対象メッシュの子にする
- Skeletal Mesh: 対象ボーンの子にする（親ボーン名をマニフェストに記録）
- **`SOCKET_` を剥がした残りがそのまま UE のソケット名**になります。
  そのため残りは `^[A-Za-z][A-Za-z0-9_]*$` を満たす必要があります
  （先頭数字 / 空白 / ハイフン / ドット / 非 ASCII は不可）。
  違反は **V-050（エラー）**で書き出し前に止まります

> **`SOCKET_1_weapon` のような名前は通りません。**マニフェストの `socket.name` は
> スキーマで `ueAssetName` として検証されるため、DCC 側で止めないと
> 「書き出しは通るのに後段で落ちる」ことになります（方針 D-3）。

> **UE 側の実装メモ**: Interchange は FBX の `SOCKET_` 命名から
> **ソケットを自前で作ります**（`UCX_` と同じ）。ただし値が壊れている
> （scale に 100 倍が混入 / 回転に -90° が残る）ため、
> 本ツールは**インポータ製を消してマニフェストの宣言値で作り直します**
> （→ [docs/99 P-17](99_作業ルール.md)）。
> **規約の書き方は変わりません**が、「インポータ任せで動いている」わけではない点に注意。

### 2.5 ボーン

| 規則 | 内容 |
|---|---|
| ルート | `root` 固定（単一） |
| 命名 | ASCII・一意・小文字スネークケース推奨（`pelvis`, `spine_01`, `hand_r`） |
| 左右 | サフィックス `_l` / `_r` |
| 連番 | 2桁ゼロ埋め（`spine_01`） |

> UE5 Mannequin 互換の命名に合わせるかは要決定（→ Q-12）

### 2.6 マテリアルスロット（規約違反はエラー: Q-19）

- Blender のマテリアル名は **`M_<名前>` 形式が必須**。違反すると**書き出しを中断**する
- 生成される Material Instance 名は `MI_<名前>`（`M_Crate_Body` → `MI_Crate_Body`）
- Blender の既定名（`Material`, `Material.001`, `マテリアル` 等）は**規約違反として弾く**
- スロットの **並び順はマニフェストの `index` で固定** する（Blender 上の並びに依存させない）

| Blender マテリアル名 | 判定 | 生成される MI |
|---|---|---|
| `M_Crate_Body` | ✔ OK | `MI_Crate_Body` |
| `M_Crate_Metal_01` | ✔ OK | `MI_Crate_Metal_01` |
| `Material` | ✖ エラー | — |
| `Material.001` | ✖ エラー（`.` 禁止・プレフィックスなし） | — |
| `crate_body` | ✖ エラー（`M_` プレフィックスなし） | — |
| `M_木箱` | ✖ エラー（2バイト文字） | — |

## 3. テクスチャサフィックス

| サフィックス | 用途 |
|---|---|
| `_BC` | BaseColor |
| `_D` | Diffuse（レガシー） |
| `_N` | Normal |
| `_ORM` | AO / Roughness / Metallic パック |
| `_M` | Metallic |
| `_R` | Roughness |
| `_AO` | AmbientOcclusion |
| `_E` | Emissive |
| `_MSK` | 汎用マスク |

> **この表が仕様の出所です。**実装（`core/texture_discovery.SUFFIXES`）はこの表と
> 一致していることを単体テストで突き合わせています
> （`tests/test_texture_discovery.py` の `TestSuffixTable` / docs/99 P-28）。
> 行を増やすときは実装・テストも同時に直してください。

### 3.1 発見規則（R-4 / 2026-10-13 追加）

ツールは **DCC 側でテクスチャを探してマニフェストに書き込みます**
（`materialSlots[].textures` / [docs/03 §10.4](03_マニフェスト仕様.md)）。
アーティストが「どのテクスチャを使うか」をツールに教える必要はありません。
**置き場と名前を規約どおりにするだけです。**

| 項目 | 規則 |
|---|---|
| 走査する場所 | `source.textureFolder`（既定 `textures/`）の**直下だけ**。**再帰しません** |
| 再帰しない理由 | 元素材フォルダ（S-11 の `megascan/`）を巻き込まないため |
| 対象拡張子 | `.png` `.tga` `.jpg` `.jpeg` `.tif` `.tiff` `.exr` |
| 大文字小文字 | **区別しません**（`t_crate_body_bc.PNG` も拾います） |
| サフィックス | **上の表にあるものだけ。**表に無いものは拾いません（`V-092` の警告） |

**ファイル名の語幹（サフィックスの手前）は、次の優先順で照合します。**
例はスロット `M_Crate_Body` / アセット `Crate_01` の場合です。

| 優先 | パターン | 例 |
|---|---|---|
| 1 | `T_<スロット名から先頭の `M_` を外した名前>_<サフィックス>` | `T_Crate_Body_BC.png` |
| 2 | `T_<スロット名そのまま>_<サフィックス>` | `T_M_Crate_Body_BC.png` |
| 3 | `T_<アセット名>_<サフィックス>`（**マテリアルスロットが1つのときだけ**） | `T_Crate_01_BC.png` |

> **優先 3 を単一スロットに限る理由**: マルチスロット（S-03 の `M_Slot_A` /
> `M_Slot_B` / `M_Slot_C`）でアセット名の語幹を許すと、
> **どのスロットに割り当てるべきか決められません。**取り違えるくらいなら拾いません。

**同じサフィックスで複数見つかったときは、黙って選びません。**

1. 語幹の優先順（上の表の 1 → 2 → 3）
2. 同じ語幹なら**拡張子の優先順**（`.png` → `.tga` → `.jpg` → `.jpeg` →
   `.tif` → `.tiff` → `.exr`）

の順で 1 枚を採用し、**採用しなかったファイル名を `V-111`（警告）に出します**。

- 見つからなかったサフィックスは**何も出力しません**（空文字やダミーは入れません）
- **`material.importTextures` が false でも `textures` は出力します。**
  「発見（DCC 側の事実）」と「取り込むか（UE 側の方針）」は別の話です（方針 D-3 / D-5）
- フォルダが無い・空でも**エラーにはなりません**。書き出しは止まりません

関連する検証: `V-110` / `V-111` / `V-112` / `V-113` / `V-114`（すべて警告・情報 /
[docs/05](05_バリデーション規則.md) §E）。

## 4. UE コンテンツフォルダ構成（たたき台）

```
/Game/
├── Props/<AssetGroup>/          SM_*, M_*, T_*
├── Environment/<AssetGroup>/
├── Characters/
│   ├── Common/                  SKEL_*（共有スケルトン）
│   └── <CharacterName>/         SK_*, PHYS_*, M_*, T_*
└── _Dev/                        検証用・最終的に削除する一時アセット
```

→ 既存プロジェクトの構成に合わせる必要があるかは Q-13。

## 5. 禁止事項

- UE の予約語・特殊文字（`.` `,` ` ` `-` `/` `\` `#` など）
- 2バイト文字（日本語を含む）
- `Copy`, `New`, `Test`, `tmp`, `aaa` 等の暫定名でのコミット
- 同一フォルダ内での大文字小文字のみの差異（Windows で衝突する）
