## 重大度の扱い

| 重大度 | 記号 | 挙動 |
|---|---|---|
| `error` | ✖ | **書き出しを中断**。中間ファイルを作らない |
| `warning` | ⚠ | 続行。マニフェストに記録し、UE 側レポートにも残す |
| `info` | ℹ | 記録のみ |

`warning` を error 扱いにする厳格モード（`strict: true`）をプリセットで設定可能にする。

> **Skeletal Mesh では以下の2つを抑止する**（どちらも「Static Mesh の話」なので誤警告になる）:

### D-5. V-069 を「警告 + 自動修正」にした判断（v0.2.0 で変更）

当初は「ズレ < 0.01 なら警告、それ以上はエラー」を検討していたが、**実測により変更した**
（docs/14 §8.3）。

| サンプル | ズレている頂点 | 最大ズレ |
|---|---|---|
| S-04 `04_skeletal_minimal` | **96 / 96**（全頂点） | `0.0230` |
| S-05 `05_skeletal_shared_skeleton` | **496 / 563** | `0.0247` |

| 論点 | 結論 |
|---|---|
| しきい値 `0.01` をエラーにすると | **ユーザーが修正済みのサンプル2件がどちらも書き出せなくなる**（0.01 超が S-04 で 24 個 / S-05 で 126 個） |
| 手付けウェイトの実態 | **1〜2% のズレは普通に出る。**これで書き出しを止めると実運用に耐えない |
| UE 側の挙動 | **UE は取り込み時に正規化する。**止める理由がない |
| 本当に実害があるもの | **V-068（ウェイト無し → 頂点が原点に吸い寄せられる）と V-070（合計ほぼ 0）だけ。**これらはエラーのまま |

→ **V-069 は警告にし、書き出し時に複製側で正規化する**（方針 D-4 により元シーンは無変更）。
自動修正したことは `auto_fixed` 付きでマニフェストに記録する。
正規化が効いていることは FBX を読み戻して確認済み（S-04: ズレ 96 頂点 → **0**）。

> `limits.weightNormalizationTolerance`（既定 `0.001`）は**警告を出すかどうかのしきい値**であり、
> **エラー判定には使わない。**

### E-1. テクスチャの発見（V-110〜V-114 / R-4 / v0.3.1 で追加）

発見規則そのものは [docs/04 §3.1](04_命名規約.md) が正。ここは**検証項目の索引**。

**走査対象は `source.textureFolder` の直下だけ**（再帰しない）。
フォルダが無い・対象拡張子のファイルが 1 つも無い場合は
**何も報告しない**（テクスチャを置いていないアセットに「見つかりません」と
言っても直しようがないため）。

| ID | 重大度 | 内容 |
|---|---|---|
| **V-110** | ⚠ | **マテリアルスロットに対応するテクスチャが 1 枚も見つからない。**照合した語幹の候補をメッセージに列挙する |
| **V-111** | ⚠ | **同じサフィックスのテクスチャが複数見つかった。**採用した 1 枚と、採用しなかったファイル名を**両方**メッセージに出す（黙って選ばない） |
| **V-112** | ⚠ | テクスチャフォルダに **`T_` で始まらない / 使えない文字を含む**ファイルがある。取り込み対象にならないことを明示する |
| **V-113** | ⚠ | **`_N`（法線）が非可逆圧縮形式（`.jpg` / `.jpeg`）。**圧縮ノイズが法線に乗る。実測: S-11 が該当（2026-10-13） |
| **V-114** | ℹ | **`_N` の画像の色空間が Blender 上で `Non-Color` でない。**UE 側はサフィックスで決めるため**取り込み結果は変わらない**（Blender 上の見た目だけの問題）。実測: S-11 が `sRGB`（2026-10-13） |

> **どれも書き出しを止めない**（Q-06）。`strict: true` のプリセットでは
> 警告（V-110〜V-113 / V-092）はエラー扱いになるが、**V-114 は情報なので昇格しない**。

> **実装上の注意**: V-114 は `bpy.data.images` のパスの末尾とファイル名を
> 突き合わせる。**`os.path.basename()` は使えない** — Blender の相対パス
> （`//textures/T_x.png`）を Windows の `ntpath` が UNC パスと解釈して
> **空文字を返す**（2026-10-13 実測。回帰テスト:
> `test_validate.py` の `test_image_colorspace_of_handles_blender_relative_paths`）。

## 自動修正（Auto-Fix）の方針

- 自動修正は **必ず複製オブジェクト上で行い、元シーンを変更しない**（設計方針 D-4）
- 自動修正した内容は `warning` としてマニフェストに必ず記録する（黙って直さない）
- 自動修正を無効化するオプションをプリセットに持たせる

## しきい値（決定済み: Q-04 / Q-06）

**すべて「超過したら警告」であり、書き出しは止めない。**プリセットで値を上書きできる。

| 項目 | 既定 | モバイル / Switch プリセット | 備考 |
|---|---|---|---|
| 最大ボーン数 | 256 | 128 | **要検証**: UE 5.8 のプラットフォーム別上限 |
| 1頂点あたり最大影響ボーン数 | 8 | 4 | |
| マテリアルスロット数上限 | 8 | 4 | ドローコール予算 |
| コリジョン三角形数上限（1形状あたり） | 32 | 32 | 物理コスト |
| テクスチャ解像度上限 | 4096 | 2048 | |
| ウェイト正規化の許容誤差 | 0.001 | 0.001 | **警告を出すかどうかのしきい値**。**エラー判定には使わない**（→ §D-5） |

対象プラットフォーム: PC / PS5 / Switch / モバイル（AAA）。VR は対象外。
