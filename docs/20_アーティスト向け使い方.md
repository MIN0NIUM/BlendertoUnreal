# 20. アーティスト向け使い方

- 最終更新: 2026-10-14
- 対象: Blender 5.2 / UE 5.8.3
- 関連: [命名規約](04_命名規約.md) / [バリデーション規則](05_バリデーション規則.md) / [実装状況](12_実装状況.md)

---

## 1. これは何か

Blender で作ったメッシュを、**ボタン1回で Unreal Engine にアセットとして取り込む**ツールです。
取り込む前に名前・スケール・UV・コリジョンなどを自動でチェックし、問題があれば日本語で教えます。
対応しているのは **Static Mesh（静的メッシュ）** と **Skeletal Mesh（スケルタルメッシュ）** です。

---

## 2. 準備（最初に1回だけ）

### 2.1 Blender 側 — アドオンを読み込む

**方法A（推奨 / 確認済み）: 専用バッチで Blender を起動する**

```bat
tools\launch_blender.bat                          （空のシーンで起動）
tools\launch_blender.bat "D:\work\Crate_01.blend" （指定の .blend を開いて起動）
```

Blender の設定を変更せず、**その起動のあいだだけ**アドオンが入ります。
Blender が見つからないと言われたら、環境変数 `BLENDER_EXE` に `blender.exe` のフルパスを設定してください。

> **こうなったら成功**: 3D ビューで `N` キーを押すとサイドバーが開き、**「ワンポチ」タブ**が出ます。

**方法B（ZIP でインストール / 手順は要検証）**

```bat
python tools\build_addon_zip.py
```

`dist\onepochi_addon_0.1.0.zip` ができます。これを Blender の
**編集 > プリファレンス > アドオン**から「ディスクからインストール」で読み込み、
**「ワンポチツール (OnePochi)」**を有効にします。

> **要検証**: ZIP の中身の構造は自動検証に合格していますが、**Blender 5.2 がどちらの形式
> （従来のアドオン形式 / 拡張機能形式）を要求するかは実機で未確認**です。
> うまくいかない場合は方法A を使ってください。

> **【スクショ差し込み位置】** Blender のプリファレンス > アドオン画面で「ワンポチツール (OnePochi)」が有効になっているところ

### 2.2 UE 側 — 取り込みの受け口を用意する

1. **スクリプトを UE プロジェクトに配置する**

   ```bat
   tools\deploy_to_ue.bat                              （既定のプロジェクトへ）
   tools\deploy_to_ue.bat "D:\MyProj\MyProj.uproject"  （指定のプロジェクトへ）
   ```

   `<プロジェクト>\Content\Python\` にコピーされます。

2. **UE プロジェクトに設定を入れる**（プラグインの有効化 + Remote Control の Python 実行許可）。
   Remote Control API は既定で Python の実行を拒否するため、この設定が要ります。
   `.uproject` を `tools\setup_ue_project.bat` へ**ドラッグ&ドロップ**するか、次を実行します。

   ```bat
   tools\setup_ue_project.bat "D:\MyProj\MyProj.uproject"
   ```

   変更内容を表示して、確認してから書き込みます（`--dry-run` を付けると見るだけです）。
   **既存の内容は残したまま**、次の2つに足りない分だけを足します。

   | 書き換えるもの | 入れる内容 |
   |---|---|
   | `<プロジェクト>\Config\DefaultRemoteControl.ini` | Python 実行の許可（許可する関数は `ExecutePythonCommandEx` の1つだけ） |
   | `<プロジェクト>.uproject` | 「Python Editor Script Plugin」と「Remote Control API」の有効化（`--no-plugins` で省略） |

   - 書き換える前の元ファイルは、`.bak-日時` を付けて横に残ります。
   - `bAllowAnyRemoteFunctionCall` などの安全側の設定がすでに別の値でも、**書き換えず警告だけ**出します。
   - 2 回流しても変わりません。

   > **なぜ Project Settings から入れないのか**: Project Settings で入れた Remote Control の設定は
   > ユーザー単位（`Saved/`）に保存され、**エディタを再起動すると失われました**（docs/99 P-29）。
   > プロジェクトの `Config/DefaultRemoteControl.ini` に置けば再起動しても残ります。
   > `DefaultEngine.ini` に書いても**読まれません**。

   手で入れる場合は、`Config/DefaultRemoteControl.ini` に次を書きます:

   ```ini
   [/Script/RemoteControlCommon.RemoteControlSettings]
   bEnableRemotePythonExecution=True
   +CustomAllowedRemoteFunctionCalls=(ClassPath="/Script/PythonScriptPlugin.PythonScriptLibrary",FunctionName=("ExecutePythonCommandEx"),bAllowChildClasses=False)
   ```

3. **UE を再起動**します（`.ini` は起動時にしか読まれません）。
   `ツール（Tools）`メニューに**「ワンポチツール」**が生えます。
   設定が効いているかは次で確認できます（UE を起動した状態で）。

   ```bat
   python tools\check_rc_config.py --project "D:\MyProj\MyProj.uproject"
   ```

> **こうなったら成功**: Blender の「ワンポチ」パネルで**「UE 接続確認」**を押すと、
> 「`http://127.0.0.1:30010` に接続できました」と緑のチェックが出ます。

> **【スクショ差し込み位置】** `setup_ue_project.bat` の実行画面（変更内容の表示と確認のところ）

> **【スクショ差し込み位置】** UE の `ツール > ワンポチツール > 最後に書き出したものを取り込む` メニュー

## 3. モデルを作るときのルール

**上にあるものほど実際に引っかかります。**詳細は [命名規約](04_命名規約.md)。

### 3.1 名前（いちばん多いエラー）

オブジェクト名・コレクション名・マテリアル名・ボーン名のすべてに効きます。

| ルール | OK | NG |
|---|---|---|
| **先頭は英字** | `Crate_01` | `01_Crate` |
| **使えるのは `A-Za-z0-9_` だけ** | `Crate_01` | `Crate-01` / `Crate 01` |
| **日本語・空白は不可** | `Crate_01` | `木箱` / `Crate 01` |
| **ドットは不可** | `Crate_01` | `Crate_01.001` |
| 大文字小文字だけの違いで区別しない | — | `crate` と `Crate` の共存 |

> **`.001` は複製したときに Blender が勝手に付けるサフィックス**です。
> 複製したオブジェクトをそのまま書き出そうとして引っかかるのが最頻パターンです。名前を直してください。

### 3.2 マテリアル名は `M_` で始める（必須）

- `M_Crate_Body` → OK
- `Material` / `Material.001` / `crate_body` / `M_木箱` → **エラー（書き出しが止まります）**
- 使っていない空のマテリアルスロットも消しておいてください

### 3.3 スケールと回転

- **スケールと回転は適用しておく**（`Ctrl+A > Scale` / `Rotation`）。
  適用し忘れても**警告だけ出して、書き出し用の複製側で自動的に適用**します（元のシーンは変わりません）
- **負のスケール（ミラー）はエラー**です。`Ctrl+A > Scale` で適用し、必要なら法線を再計算してください

### 3.4 UV

- **UV0 は必須**（無いとエラー）
- UV1（ライトマップ用）は無くても警告だけです。UE 側で自動生成されます

### 3.5 コリジョン

形式は `<プレフィックス>_<本体メッシュ名>_<2桁連番>`。例: 本体が `Crate_01` なら `UCX_Crate_01_01`。

| プレフィックス | 形状 |
|---|---|
| `UCX_` | 凸包 |
| `UBX_` | ボックス |
| `USP_` | スフィア |
| `UCP_` | カプセル |

- **連番は省略できますが、省略しないでください**（警告が出ます）。`UCX_Crate_01` は
  「本体 `Crate_01` の連番なし」とも「本体 `Crate` の1番」とも読めて、曖昧になります
- `UCX_` は**閉じた形状**にしてください（開いた面があるとエラー）。凹んでいると警告が出ます
  （UE は凸包として扱うため、意図しない形になります）
- コリジョンメッシュにマテリアルは要りません（付いていると警告）

### 3.6 ソケット

- **Empty オブジェクト**を置き、名前を `SOCKET_<ソケット名>` にします。例: `SOCKET_Lid`
- Static Mesh では**本体メッシュの子**に、Skeletal Mesh では**対象ボーンの子**にします
- `SOCKET_` を外した残りがそのまま UE のソケット名になるので、**残りも英字で始まる名前**にしてください
  （`SOCKET_1_weapon` はエラー）

### 3.7 LOD（使うときだけ）

LOD を使う場合は、UI の**「対象の指定」を「コレクション」**にする必要があります（選択モードでは LOD0 のみ）。

```
Crate_01/                 ← アセット名と同じ名前のコレクション
├── LOD0/                 ← 必須。欠番は不可
│   └── Crate_01          ← LOD0 は素のアセット名
├── LOD1/
│   └── Crate_01_LOD1     ← LOD1 以降は _LOD<n> を付ける
├── LOD2/
│   └── Crate_01_LOD2
├── Collision/
│   └── UCX_Crate_01_01
└── Sockets/
    └── SOCKET_Lid
```

- `LOD<n>` / `Collision` / `Sockets` は**予約語**です。他の用途に使わないでください
- **LOD1 以降のオブジェクト名に `_LOD<n>` を付ける**のは、Blender がオブジェクト名を
  ファイル全体で一意に保つため（同名にすると勝手に `.001` が付きます）
- **全 LOD でマテリアル構成を揃えてください**（違うとエラー）
- 三角形数は段が進むごとに減らしてください（増えていると警告）

> **【スクショ差し込み位置】** Blender のアウトライナで、上記の `LOD0` / `LOD1` / `Collision` / `Sockets` 構成が見えている状態

### 3.8 Skeletal Mesh のとき

- **ルートボーンは1本だけ**、名前は `root`、**ワールド原点**に置く
- **ルートボーンに少しだけウェイトを割り当てる。**ウェイトが無いボーンは書き出し時に削除されるため、
  ルートごと消えてしまいます
- ボーン名も §3.1 のルールに従います（ASCII / 先頭英字）
- **ウェイトが割り当たっていない頂点はエラー**です（UE では原点に吸い寄せられます）。
  合計が 1.0 になっていない程度のズレは警告だけで、**書き出し用の複製側で自動的に正規化**します
- ポーズにスケールを入れないでください（`Pose > Clear Transform > Scale`）。
  書き出しは rest 姿勢で行うため、ポーズの移動・回転は反映されません（警告が出ます）
- Shape Key（モーフターゲット）を使うときは、**先頭ブロックを `Basis`** にしてください

## 4. 使い方

### 手順1. `.blend` を保存する

→ **成功の目印**: タイトルバーにファイルのパスが出る。
未保存のままだと「`.blend` ファイルが保存されていません」の警告、
さらに「アセットフォルダ」も空だとエラーで止まります。

### 手順2. 書き出すものを指定する

| 方法 | やること |
|---|---|
| **選択オブジェクト**（既定） | 本体メッシュ・コリジョン・ソケットの Empty を**まとめて選択**する。<br>Skeletal Mesh では **Armature を選べば**、それにスキンされたメッシュを自動で拾います |
| **コレクション** | 「対象の指定」を「コレクション」にして、「コレクション」欄にアセット用コレクションを指定する。<br>**LOD を使うときはこちら** |

### 手順3. 「ワンポチ」パネルを設定する

`3D ビュー` で `N` キー → サイドバーの**「ワンポチ」タブ** → **「ワンポチツール」**パネル。

| 項目 | 内容 |
|---|---|
| **プリセット** | `prop`（小物）/ `environment`（背景）/ `character`（キャラクター）など。設定の束です |
| **出力環境** | `Dev（検証用）` が既定。**`本番` は `/Game` 直下に直接書き出す**ので赤い警告が出ます |
| **アセット種別** | `Static Mesh` / `Skeletal Mesh` |
| **対象の指定** | `選択オブジェクト` / `コレクション`（手順2） |
| **アセット名** | UE 側の名前のベース。`SM_` / `SK_` は自動で付きます。<br>右の**スポイトボタン**でアクティブなオブジェクトから補完できます |
| **アセットフォルダ** | 空なら `.blend` の置き場。この下の `fbx\` に書き出します |
| **UE 出力先** | 空ならプリセットから自動で決まります |
| **マテリアル** | `プリセットに従う` / `何もしない` / `既存を割当` / `MI を生成` |

> **【スクショ差し込み位置】** Blender のサイドバー「ワンポチ」タブのパネル全体（設定が埋まった状態）

### 手順4. 「チェックのみ」を押す

書き出さずに検証だけします。

→ **成功の目印**: 画面下に「**問題なし**: …」と出て、**「検証結果」リストに ✖ の行が無い**。
警告（⚠）は残っていても書き出せます。リストの行をクリックすると、その対象オブジェクトが選択されます。

### 手順5. 「UE 接続確認」を押す

→ **成功の目印**: 「`http://127.0.0.1:30010` に接続できました」と出る。
出なければ §2.2 の設定か、UE が起動しているかを確認してください。

### 手順6. 「UE へ自動インポート」にチェックを入れて「ワンポチ」を押す

検証 → 整形 → FBX 出力 → マニフェスト出力 → UE への取り込みまで一気に走ります。

→ **成功の目印**: 「**UE への取り込み完了**: `/Game/_Dev/…/SM_Crate_01`」と出て、
パネルの Unreal Engine 欄に緑のチェックが付く。

### 手順7. UE で確認する

コンテンツブラウザに `SM_<アセット名>`（または `SK_<アセット名>`）ができています。

> **【スクショ差し込み位置】** UE のコンテンツブラウザに `SM_Crate_01` が生成された状態

**別の送り方**

- 自動インポートを OFF にして「ワンポチ」→ あとから**「UE へ取り込む」**を押す
  （書き出しをやり直さず、直前のマニフェストをもう一度送ります）
- **UE 側から**: `ツール > ワンポチツール > 最後に書き出したものを取り込む`。
  結果はダイアログで表示されます
- **「出力先を開く」**ボタンで、FBX とマニフェストが置かれたフォルダをエクスプローラで開けます

## 5. よくあるエラーと対処

✖ = エラー（書き出しが止まる） / ⚠ = 警告（続行する）

| ID | エラー文（抜粋） | 何が起きているか | どう直すか |
|---|---|---|---|
| ✖ V-102 | `.blend が未保存で、アセットフォルダも指定されていません` | 書き出し先が決まらない | `.blend` を保存する。または「アセットフォルダ」を指定する |
| ✖ V-001 | `書き出し対象のメッシュが1つもありません` | 選択が空、またはコレクションにメッシュが無い | メッシュを選択する。Skeletal Mesh なら Armature を選ぶ |
| ✖ V-003 系 | `名前にドットが含まれています（Blender の重複サフィックス .001 などは不可）`<br>`名前が数字で始まっています`<br>`名前に ASCII 以外の文字（日本語など）が含まれています` | 命名規約違反（→ §3.1） | 名前を `A-Za-z0-9_` だけ・英字始まりに直す。`.001` は複製の痕跡なので手で直す |
| ✖ V-003c | `Blender の既定マテリアル名のままです（'Material'）。M_<名前> 形式に変更してください` | マテリアル名が規約違反（→ §3.2） | `M_Crate_Body` のように `M_` を付ける。使っていないスロットは削除する |
| ⚠ V-006 / V-007 | `スケールが適用されていません（…）。書き出し用の複製側で適用します` | スケール・回転が未適用。**自動で直します** | そのまま進んで構いません。気になるなら `Ctrl+A > Scale` / `Rotation` |
| ✖ V-009 | `負のスケール（ミラー）が残っています。行列式が負です` | ミラー複製などで負のスケールが残っている | `Ctrl+A > Scale` で適用し、必要なら法線を再計算（`Shift+N`） |
| ✖ V-025 | `UV が1つもありません（UV0 は必須）` | UV が展開されていない | UV を展開する。UV1 が無いだけなら警告（V-026）で通ります |
| ✖ V-041<br>⚠ V-040 | `コリジョン 'UCX_Crate' に対応する本体メッシュ 'Crate' が書き出し対象にありません`<br>`コリジョン名に連番がありません` | コリジョンの名前が本体メッシュ名と噛み合っていない（→ §3.5） | `UCX_<本体メッシュ名>_01` の形に直す。本体も一緒に選択する |
| ✖ V-042<br>⚠ V-043 | `凸包コリジョンが閉じた多面体になっていません`<br>`凸ではありません（8/13 面が凸条件を満たしません）` | `UCX_` の形が開いている / 凹んでいる | 穴を閉じる。凹形状は分割して複数の `UCX_` にする |
| ✖ V-050 | `ソケット名 '1_weapon' が規約に合いません（…）。SOCKET_<英字で始まる名前> にしてください` | `SOCKET_` の後ろが UE のアセット名規約に合っていない | `SOCKET_weapon_r` のように英字始まりにする |
| ✖ V-045 / V-046 | `LOD コレクションに欠番があります（検出: [0, 2] / 期待: [0, 1]）`<br>`LOD1 のマテリアル構成が LOD0 と一致しません` | LOD コレクションの構成が規約と違う（→ §3.7） | `LOD0` から連番で作る。全 LOD のマテリアル構成を揃える |
| ✖ V-060<br>✖ V-062 | `Skeletal Mesh として書き出すには Armature が必要です`<br>`ルートボーン 'root' にウェイトが無く …ルートが削除されます` | Armature が対象に入っていない / ルートにウェイトが無い | Armature を同じコレクション（または選択）に含める。ルートにウェイトを少量割り当てる |
| ✖ V-068 / V-070 | `スキンウェイトが無い頂点が 12 個あります（頂点 index: … ）。UE では原点に吸い寄せられます` | ウェイトの塗り漏れ | ウェイトを塗る。合計が 1.0 でないだけなら警告で、自動的に正規化されます |

**UE への取り込みで失敗したとき**

| 症状 | 原因 | 対処 |
|---|---|---|
| `UE の Remote Control で Python の実行が許可されていません` | セキュリティ設定が入っていない | §2.2 の 2 のとおり `tools\setup_ue_project.bat` を実行し、**UE を再起動**する |
| `ExecutePythonCommandEx の呼び出しが許可リストに入っていません` | 関数の許可リスト未設定 | §2.2 の 3 の 3 行目を設定する |
| `UE の Python プラグインが見つかりません` | Python プラグインが無効 | 「Python Editor Script Plugin」を有効にする |
| `UE に接続できません（http://127.0.0.1:30010）` | UE が起動していない / Remote Control API が無効 | UE を起動する。「Remote Control API」プラグインを有効にする |

## 6. UE 側で何が起きるか

### 6.1 どこに何ができるか

- **出力先**: 「UE 出力先」が空なら、プリセットから自動で決まります。
  `prop` プリセット + `Dev` 環境なら `/Game/_Dev/Props/SM_Crate_01/` フォルダの中に `SM_Crate_01` ができます。
  フォルダを自分で決めたいときは「UE 出力先」に `/Game/_Dev/Props/Crate_01` のように入れてください
- **`Dev（検証用）` 環境では `/Game/_Dev` の外には書けません**（安全装置です）

| 生成されるもの | 名前の例 | 備考 |
|---|---|---|
| Static Mesh | `SM_Crate_01` | コリジョン・ソケット・LOD は**この中**に入ります（別アセットになりません） |
| Skeletal Mesh | `SK_Dummy_Body` | |
| Skeleton | `SK_Dummy_Body_Skeleton` | 既存の Skeleton を流用する設定も可能です |
| マテリアルインスタンス | `MI_Crate_Body` | 「マテリアル」で **`MI を生成`** を選んだときだけ。<br>マスターマテリアルが無ければ自動で作られます |

> **「マテリアル」を `何もしない` にしていても、UE のインポータが FBX のマテリアルから
> マテリアルインスタンスを自動で作ります。**その名前は Blender のマテリアル名のまま（`M_Crate_Body`）で
> 命名規約（`MI_`）に合わないため、レポートに警告が出ます。規約どおりにしたいときは `MI を生成` を使ってください。

### 6.2 もう一度取り込んだとき（再インポート）

**同じ場所に取り込み直しても、UE 側で手作業した設定は残ります。**
レポートの `action` が `created`（新規）から `reimported`（再取り込み）に変わります。

| 残るもの | 状態 |
|---|---|
| Nanite の有効/無効 | **実機で確認済み** |
| ライトマップ解像度 | **実機で確認済み** |
| 手で追加したソケット（マニフェストが宣言していない名前のもの） | **実機で確認済み** |
| コリジョン / マテリアル割当 / Build Settings | 実装済み・**要検証** |

**マニフェストの値で上書きしたい項目だけ**、プリセットやアセット設定の
`reimportPolicy.override` に挙げます。挙げられるのは
`nanite` / `lod` / `collision` / `lightmap` / `materials` / `sockets` / `buildSettings` の7つです。

> **Skeletal Mesh の再インポートでは設定の保持は行いません**（下の §7）。
> その場合はレポートに日本語の警告が残り、取り込み自体は成功します。

## 8. 困ったときの報告の仕方

次の3つを添えて報告してください。これだけで、ほとんどの原因が分かります。

1. **マニフェスト**: `<アセットフォルダ>\fbx\onepochi.json`
2. **UE 側のレポート**: `<アセットフォルダ>\fbx\ue_report.json`
3. **実行ログ**: `%LOCALAPPDATA%\OnePochi\runs\<run_id>\`（フォルダごと。`onepochi.json` と `result.json` が入っています）

- 1 と 2 のフォルダは、パネルの**「出力先を開く」**ボタンで開けます
- 3 の最新の場所は `%LOCALAPPDATA%\OnePochi\runs\latest.json` に書かれています。
  **実行ログは 30 日ぶん残ります**。`fbx\` の中身は書き出すたびに上書きされるので、
  「前回うまくいっていたときの値」はこちらにしか残りません

あわせて、次があると助かります。

- **Blender のコンソールの `[ワンポチ]` から始まる行**
  （Windows なら `ウィンドウ` メニューのシステムコンソール表示の項目で出せます）
- **UE の Output Log**
- 「検証結果」リストに出ていたエラーの ID（`V-003c` など）と文面
