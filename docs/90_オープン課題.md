## 2. 決定を受けた設計変更

### 2-1. Q-17 → アーキテクチャを「2層 + トリガー」に整理

ご指示「Blender→アセット元データ、アセット元データ→Unreal のフローを独立させ、Blender 側 UI から UE へのインポートまでできるようにしたい」をそのまま構造にします。

```
┌── 第1層: Blender → アセット元データ ──────────────────────┐
│  Blender アドオン                                          │
│   検証 → 複製整形 → FBX 出力 → onepochi.json 出力          │
│  成果物は「アセット元データフォルダ」に残る（§2-3）          │
└────────────────────────────────────────────────────────────┘
                         ↓ onepochi.json のパスを渡すだけ
┌── 第2層: アセット元データ → Unreal ───────────────────────┐
│  UE Python: import_from_manifest(manifest_path) -> report  │
│  ★ この関数は「起動方法を一切知らない」純粋な処理（方針 D-1）│
└────────────────────────────────────────────────────────────┘
          ↑ 第2層を叩く経路は3つ。どれも同じ関数を呼ぶ
   (a) UE エディタのボタン（Editor Utility Widget）
   (b) HTTP ＝ Blender の UI ボタンから直接（★ これが「ワンポチ」）
   (c) コマンドライン（将来の CI / バッチ）
```

**(b) の実現手段**: UE の **Remote Control API**（公式・Experimental ではない）を使う。
公式 MCP プラグインは Experimental かつ AI エージェント向けなので、**製品の実行経路には使わない**。

> **要検証**: UE 5.8 の Remote Control API の既定ポート・エンドポイント仕様・Python 関数の呼び出し方法。

この構造の利点: 第2層は FBX と onepochi.json しか見ないため、将来 Houdini から同じものを出力すれば**UE 側は無改造で動く**。

### 2-2. Q-11 → LOD はコレクション方式。ただし「Nanite なら LOD 不要」は条件付き

**ご質問「Naniteなら背景LODは必要なくない？」への回答:**

| 論点 | 回答 |
|---|---|
| UE のアセット一覧が煩雑になる心配 | **なりません。**UE の Static Mesh の LOD は**アセット内部**に格納されるため、LOD ごとに別アセットは作られません。煩雑になるのは Blender 側のオブジェクト名だけ。→ コレクション方式にするご判断は妥当です |
| Nanite があれば LOD 不要か | **対象プラットフォームに Switch とモバイルが入っているので「不要」とは言えません。** PC/PS5 は Nanite で LOD 不要にできますが、Nanite が使えない経路のための **Fallback Mesh** が必要になります。また **Skeletal Mesh には Nanite が効きません**（UE 5.8 での対応状況は要検証） |

**結論（プリセットで切り替える）:**

| プリセット | Nanite | LOD |
|---|---|---|
| `environment`（PC/PS5 背景） | ON | `auto`（Fallback 用に自動生成のみ） |
| `environment_mobile`（Switch/モバイル背景） | OFF | `manual`（コレクションから取得） |
| `prop` | OFF | `none`（必要なら `manual`） |
| `character` | OFF | `none`（スケルタルLODは v2） |

**Blender 側の LOD 表現（決定）:**

```
Crate_01/                      ← アセット用コレクション（= アセット名）
├── LOD0/                      ← コレクション名で LOD レベルを表す
│   └── Crate_01               ← オブジェクト名に _LOD は付けない
├── LOD1/
│   └── Crate_01
├── Collision/
│   ├── UCX_Crate_01_01
│   └── UBX_Crate_01_01
└── Sockets/
    └── SOCKET_Lid
```

- LOD コレクションが無い場合は「LOD0 のみ」とみなす（単純なアセットで階層を強制しない）
- `LOD0` は必須。`LOD0, LOD2` のような欠番はエラー

### 2-3. Q-07 → ExchangeRoot は廃止。アセット元データフォルダに置く

**ご質問「ExchangeRoot は何に使うのか」への回答と、それを踏まえた変更:**

当初の意図は「DCC が書き出した FBX と設定を UE が拾う中継置き場」でした。目的は 3つ
—(a) FBX を UE プロジェクト内に入れない、(b) 実行ごとの記録を残して再現・デバッグできる、(c) UE が見る場所を 1箇所に固定する。

**ただし、ご提示いただいたフォルダ構成があれば中継置き場は不要です。** FBX は .blend の隣に置くのが
最も追跡しやすく、コピーの二重管理も起きません。(c) も、Blender の UI から UE を直接叩く方式（§2-1 (b)）なら
「UE が探しに行く」必要がそもそもありません。

**変更: `ExchangeRoot` を廃止し、以下の構成を正とします。**

```
<AssetsRoot>/
└── Crate_01/                      ← フォルダ名 = アセット名（先頭数字禁止）
    ├── Crate_01.blend             ← 元データ
    ├── onepochi_asset.json        ← ★ 手で編集する設定（UEインポート先など）
    ├── fbx/
    │   ├── SM_Crate_01.fbx        ← 書き出し成果物
    │   └── onepochi.json          ← ★ 自動生成されるマニフェスト
    ├── textures/                  ← UE に持っていくテクスチャ
    ├── substance/                 ← 作業データ（UE には持っていかない）
    └── houdini/                   ← 作業データ（UE には持っていかない）
```

- `onepochi_asset.json` = **人間が書く**設定ファイル（ご提案の「メモったテキストファイル」の役割）。
  UE インポート先パス、プリセット名、アセット種別などを記述。テキストエディタで直接編集できる
- `onepochi.json` = **ツールが書く**マニフェスト。`onepochi_asset.json` + プリセット + シーン実測値を
  展開した最終値。UE 側はこれだけを見る
- 実行ログ（`ue_report.json` 等）は `%LOCALAPPDATA%/OnePochi/runs/<run_id>/` に置く（メッシュは置かない。
  小さな JSON だけなので容量を気にせず 30日保持）

> `AssetsRoot` の実際の場所はご指定ください（→ §3 の残課題 R-1）。

### 2-5. Q-19 → マテリアル / MI の扱い

1. **マスターマテリアルは仮のものを Claude が作成**（`M_OnePochi_Base`: BaseColor / Normal / ORM / Emissive のパラメータを持つ最小構成）

4. **マテリアル名が命名規約に合わない場合はエラーにして書き出しを止める**（Q-19 のご指示どおり）

### 3-1. R-1 → パスはすべてプリセットから差し替え可能にした

DCC データフォルダの構造（§2-3）を**コードに固定せず**、プリセットの `dccLayout` で宣言する
（設計方針 D-2）。

```json
"dccLayout": {
  "fbxSubdir": "fbx",
  "texturesSubdir": "textures",
  "substanceSubdir": "substance",
  "houdiniSubdir": "houdini",
  "manifestName": "onepochi.json",
  "reportName": "ue_report.json"
}
```

| 差し替えたいもの | 方法 |
|---|---|
| サブフォルダ名・マニフェスト名 | プリセットの `dccLayout`（アセット単位なら `onepochi_asset.json` で上書き） |
| プリセットの置き場所 | 環境変数 `ONEPOCHI_PRESET_DIR` |
| アセット設定ファイルの名前 | 環境変数 `ONEPOCHI_ASSET_CONFIG_NAME` |
| アセットフォルダそのもの | Blender UI の「アセットフォルダ」/ `run_headless.py --asset-folder`（空なら `.blend` の置き場） |

> `export.outputSubdir` は `dccLayout.fbxSubdir` に一本化して**削除**した。
> 同じ意味の設定が2箇所にあると必ず食い違う。

### 3-2. R-2 → 環境（Dev / 本番）をプリセットで切り替える

`destination.environments` で `contentRoot` と `pathWhitelist` をまとめて切り替える。
`pathTemplate` の `{contentRoot}` がその値に展開される。

```json
"destination": {
  "environment": "dev",
  "environments": {
    "dev":        { "contentRoot": "/Game/_Dev", "pathWhitelist": ["/Game/_Dev"] },
    "production": { "contentRoot": "/Game",      "pathWhitelist": ["/Game"] }
  },
  "pathTemplate": "{contentRoot}/{assetName}"
}
```

| プリセット | dev | production |
|---|---|---|
| `prop` | `/Game/_Dev/Props/Crate_01` | `/Game/Props/Crate_01` |
| `character` | `/Game/_Dev/Characters/Hero_01` | `/Game/Characters/Hero_01` |

**既定は `dev`。**本番を汚す側ではなく安全側に倒す。切り替え方は3つ:

1. プリセットの `destination.environment`（`sample_debug` は `dev` に固定）
2. Blender UI のドロップダウン「出力環境」— **`production` を選ぶと赤い警告行が出る**
3. `run_headless.py --environment dev|production`

ホワイトリストは環境に追従するので、**dev を選んでいる間は `/Game/Props` への書き込みが
UE 側で拒否される**（V-004 / `manifest_io.check_destination`）。
選択した環境はマニフェストの `destination.environment` に記録され、UE 側のレポートに残る。

未定義の環境名を指定した場合は **V-105** でエラーにし、使える名前を列挙する。

### 3-3. R-3 → `addons/` 配下へ移動した（実測で判明した必須の変更）

**Blender はアドオンを `<script_dir>/addons/` の下しか探さない。**
背景 Blender で実測した結果:

```
script_paths():        [..., 'C:\...\tools\dcc_blender']   ← 登録は効いている
script_paths(addons):  []                                    ← addons/ が無いので空
addon_utils.modules() → onepochi: 見つからない
```

そのため `tools/dcc_blender/wanpochi/` → **`tools/dcc_blender/addons/onepochi/`** へ移した。
移動後は `addon_utils.enable("onepochi")` が成功し、`Scene.onepochi` とオペレータ群が登録される
（実測で確認）。

| 項目 | 内容 |
|---|---|
| Script Directory に登録するパス | `tools/dcc_blender`（**`addons` は付けない**。Blender が自動で付ける） |
| アドオン本体 | `tools/dcc_blender/addons/onepochi/` |
| インストール不要の読み込み | `tools/dcc_blender/bootstrap_addon.py`（`addons/` を `sys.path` に入れる） |

> **実測で分かった注意点**: 確認時点で `preferences.filepaths.script_directories` が
> **空**でした。登録が保存されていないので、**再登録してプリファレンスを保存**してください
> （docs/13 の A-6）。
