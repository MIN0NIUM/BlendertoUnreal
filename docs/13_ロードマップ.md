| K-2 | ~~**Interchange が `UCX_` 等のコリジョン規約を honor しない**~~ → **✅ 解消済み** | — | **実測で honor することを確認**（S-02 で convex 1 + box 1 が簡易コリジョンとして入り、別アセットにならなかった）。加えて、**コリジョン無しの FBX に Interchange が凸1個を自動生成する**ことも判明したが、`collision.simple = "none"` 宣言時は**ポストプロセスで削除して制御できる**ことを確認（[docs/12](12_実装状況.md) C-7 / I-8） |
| K-2b | ~~**Interchange が `SOCKET_` 規約を honor しない**~~ → **honor するが値が壊れている** | ソケットが 100 倍スケールで入る / 同名が2個できる | **インポータ製を消して宣言値で作り直す**（方針 D-6）。`get_sockets_by_tag("")` で**総数を実測**して重複を検知する。往復テストの比較項目に入れた（[99 P-17](99_作業ルール.md)） |
| K-8 | **インポータが「気を利かせて」作ったものを、存在確認だけで合格にしてしまう** | 壊れた値のまま出荷する | **値まで実測して比較項目にする。**コリジョン（I-8）とソケット（I-19）で2回踏んだ。新しい要素を足すときは必ず `comparison` に項目を作る |
| K-3 | **UE 5.8 の公式 MCP が Experimental で API が変わる** | 開発補助が壊れる | **本番経路には使わない**と決定済み。壊れても製品に影響しない |
| K-4 | **Blender の FBX エクスポータ引数がバージョンで変わる** | 書き出し設定が無言で効かなくなる | 実オペレータのプロパティと**照合してフィルタし、未知の引数を警告として記録**する実装済み |
| K-5 | **UE Python API が届かない設定がある** | 一部の設定が自動化できない | 全 API 呼び出しを個別に try で囲み**レポートに残す**実装済み。届かないものが判明したら Q-14 の方針どおり **C++ へ部分移行** |

| K-7 | **アーティストが規約を守らない** | 事故が再発する | バリデーションで**機械的に止める**。`M_` 形式でないマテリアル名は書き出し自体を中断（Q-19） |
