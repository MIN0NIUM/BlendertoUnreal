#### 制約が1つ消えました（T-1b の解消）

1. `Skeleton.get_skeleton_preview_mesh()` — Interchange が作った Skeleton には取り込み元が入っている
2. アセットレジストリの `Skeleton` タグ検索 — プレビュー未設定でも参照メッシュから拾える

結果、**`method: "skeletonModifier"`**（親子関係まで比較した合格）になりました。

> `/Engine` 配下の Skeleton では `SkeletonModifier` が階層を読めません（実測）。

## 2. 作業中に見つけて直した実バグ（指示に無かったもの）

### H-1. `UCX_Crate_01` が V-041 で止まる（コリジョン名の曖昧さ）

- **症状**: S-08 で「コリジョン `UCX_Crate_01` に対応する本体メッシュ `Crate` が
  書き出し対象にありません」（V-041 エラー）。本体は `Crate_01` なのに
- **原因**: `parse_collision_name()` が末尾の `_01` を**連番として剥がしていた**。
  `UCX_Crate_01` は「本体 `Crate_01` の連番なし」とも「本体 `Crate` の 1 番」とも読め、
  **`<名前>_<2桁>` は本プロジェクトの標準的なメッシュ名**なので誤読が常態化する
- **対応**: `parse_collision_name(name, known_bodies)` に**書き出し対象の本体メッシュ名の一覧**を
  渡し、**実在する読み方を優先**する。どちらも実在しなければ従来の規則で返して V-041 に判定させる
- **波及**: `bl/collect.py` の2か所（選択モード / コレクションモード）で本体名を先に確定させた
- **テスト**: `test_core.py` に4件（文脈なしの従来挙動 / 文脈ありの優先 / 連番付きの本体 / どちらも不一致）
- **記録**: docs/99 **P-19** / docs/04 §2.3

> これは**サンプルの問題ではなくツールの設計欠陥**でした。`Crate_01` のような
> 名前に単一コリジョンを付けるのは極めて普通の操作なので、放置すると全員が踏みます。

### H-2. UE 側にソケットが2個できていた（インポータ製と重複）

- **症状**: `socketTransforms` の比較が不一致。`find_socket("Lid")` が返す値は
  **回転に -90° / スケールに 100 倍**が混入していた
- **原因**: **Interchange が FBX の `SOCKET_` 命名からソケットを自前で作る**
  （`UCX_` のコリジョンと同じ）。そこへポストプロセスが追加していたため**同名が2個**になり、
  `find_socket()` は**インポータ製のほう**を返していた
- **実測したインポータ製の値**（UE 5.8.3）:

  | 項目 | インポータ製 | 宣言値（正しい） |
  |---|---|---|
  | location | `(0, -0, 100)` | `(0, 0, 100)` ✅ 一致 |
  | rotation | `(-76.2103, -15.6831, 20.228)` | `(-13.7897, 15.6831, 20.228)` |
  | scale | **`(100, 100, 100)`** | `(1, 1, 1)` |

  **scale 100 倍は明確な誤り**（ソケットに付けたものが 100 倍になる）。
  roll は Blender の X 回転から 90° を引いた値で、pitch の符号も逆

- **対応**: 方針 D-6 のとおり**インポータ製を消して宣言値で作り直す**
  （`postprocess.remove_existing_sockets()`）。消すのは**マニフェストが宣言した名前だけ**なので、
  UE 側で手で足した別名のソケットは残ります
- **重複の検知**: `StaticMesh.sockets` は protected で読めませんが、
  **`get_sockets_by_tag("")` で全列挙できる**ことを実測しました。
  `find_socket()` は先頭1個しか返さないので、**総数を実測しないと重複を見逃します**。
  `comparison.sockets.actualTotal` として比較項目に入れ、
  **再インポートを3回繰り返しても1個のまま**であることを確認しました
- **記録**: docs/99 **P-17** / docs/13 K-2b / K-8

### H-3. 自分で入れたバグ（`void` を返す API の成否判定）

H-2 の修正で「同名ソケットを無くなるまで消す」ループを書いたところ、

`StaticMesh.remove_socket()` は**成功しても `None`（void）**なので、
`if attempt(...) is None: break` が成功を失敗と読んでいました。

**`get_sockets_by_tag("")` で総数を実測していたおかげで気づけました**
（`find_socket()` だけ見ていたら「直った」と誤認していました）。
→ docs/99 **P-18** に記録。
